🌐 API Dokümantasyonu

📌 Genel Bilgiler

  • Base URL: http://localhost/api (Production: https://securebox.local/api)
  • API Version: v1
  • Authentication: JWT Bearer Token (Header: Authorization: Bearer {token})
  • Content-Type: application/json
  • Swagger UI: http://localhost/api/swagger

🔐 Authentication Endpoints

POST /v1/auth/login

Açıklama: Kullanıcı girişi (username ve password ile)

Auth Gerekli: ❌ Hayır

Request Body:

{ "username": "admin", "password": "Admin@123" }

Response (200 OK):

{ "success": true, "data": { "accessToken": "eyJhbGc...", "refreshToken": "eyJhbGc...", "expiresIn": 900, "tokenType": "Bearer", "user": { "userId": "guid", "username": "admin", "email": "admin@securebox.local", "roles": ["Admin"] } }, "message": "Login successful" }

Hata Kodları:

  • 401 INVALID_CREDENTIALS - Geçersiz kullanıcı adı veya şifre
  • 500 LOGIN_ERROR - Sunucu hatası
POST /v1/auth/refresh

Açıklama: Access token yenileme (refresh token kullanarak)

Auth Gerekli: ❌ Hayır

Request Body:

{ "refreshToken": "eyJhbGc..." }

Response (200 OK):

{ "success": true, "data": { "accessToken": "eyJhbGc...", "expiresIn": 900, "tokenType": "Bearer" } }
POST /v1/auth/change-password

Açıklama: Kullanıcı şifre değiştirme

Auth Gerekli: ✅ Evet

Request Body:

{ "currentPassword": "OldPass123!", "newPassword": "NewPass123!", "confirmPassword": "NewPass123!" }

Açıklama: Yeni anahtar oluştur

Auth Gerekli: ✅ Evet

Request Body:

{ "name": "DATABASE_PASSWORD", "description": "Production DB password", "keyType": "Password", "value": "SuperSecretPassword123!", "certificateId": "guid", "encryptionAlgorithm": "AES256", "environmentTag": "PROD", "tags": ["database", "production"], "validFrom": "2025-11-07T00:00:00Z", "validTo": "2026-11-07T00:00:00Z" }
POST /v1/keys/{keyId}/retrieve

Açıklama: Anahtar değerini al (decrypt) - Triple Authentication

Auth Gerekli: ✅ Evet + Certificate + Password

⚠️ Triple Authentication

Bu endpoint, hassas anahtar değerlerine erişim için üç faktörlü kimlik doğrulama gerektirir:

  • 1. Faktör: JWT Access Token (Authorization header)
  • 2. Faktör: Certificate Thumbprint
  • 3. Faktör: User Password (re-authentication)

Her erişim detaylı olarak audit log'a kaydedilir (IP, UserAgent, Timestamp).

Request Body:

{ "reason": "Deploy to production server" }

Response (200 OK):

{ "success": true, "data": { "keyId": "guid", "name": "DATABASE_PASSWORD", "value": "SuperSecretPassword123!", "expiresAt": "2026-11-07T00:00:00Z", "retrievedAt": "2025-11-07T07:00:00Z" } }

🔒 Güvenlik Mimarisi

🔐 Şifreleme Mekanizmaları

1. Anahtar Şifreleme (AES-256-GCM)

Tüm hassas key value'lar AES-256-GCM (Galois/Counter Mode) ile şifrelenir:

  • Algoritma: AES-256-GCM
  • Key Size: 256 bit
  • IV (Initialization Vector): 16 bytes (her şifreleme için unique)
  • Authentication Tag: 16 bytes (integrity check)
  • Certificate-Based: X.509 certificate private key ile master key şifreleme

Şifreleme Akışı:

1. User, key value girer: "SuperSecret123!" 2. Random IV generate edilir (16 bytes) 3. Certificate'ten encryption key türetilir 4. AES-256-GCM ile şifreleme: Ciphertext = AES-GCM.Encrypt(plaintext, key, IV) 5. Authentication Tag oluşturulur (integrity) 6. PostgreSQL'e kaydedilir: - EncryptedValue: ciphertext - EncryptionIV: IV - EncryptionTag: tag - CertificateId: sertifika referansı

2. Password Hashing (BCrypt)

  • Algoritma: BCrypt
  • Work Factor: 11 (2^11 iterations)
  • Salt: Otomatik random salt (hash'e embedded)
  • Rainbow Table Koruması: Salt sayesinde
  • Timing Attack Koruması: Constant-time comparison

3. JWT Token Güvenliği

  • Algoritma: HS256 (HMAC-SHA256)
  • Secret Key: 256-bit secret (environment variable)
  • Access Token Expiry: 15 dakika
  • Refresh Token Expiry: 7 gün
  • Claims: userId, username, roles, permissions
  • Token Revocation: Redis blacklist (logout)

🛡️ Triple Authentication

🔐 Üç Faktörlü Kimlik Doğrulama

Hassas işlemler (key retrieve, key rotate) için üç faktör gereklidir:

  1. 1. JWT Token (Something You Have)

    Authorization header'da Bearer token

  2. 2. Certificate Thumbprint (Something You Have)

    Valid certificate ownership kanıtı

  3. 3. User Password (Something You Know)

    Re-authentication (şifre tekrar girilir)

Kullanım Senaryosu: Key retrieve, certificate revoke, user deletion gibi kritik işlemler.

📝 Audit Trail

✅ Audit Logging Stratejisi

  • Multi-Store: PostgreSQL (summary) + MongoDB (detail) + ELK (search)

  • Severity Levels: Info, Warning, Critical
  • Compliance: GDPR, ISO 27001 compliance ready

Audit Edilen İşlemler:

  • Login/Logout
  • Key Create/Retrieve/Rotate/Revoke/Delete
  • Certificate Upload/Revoke/Delete
  • User Create/Update/Delete
  • Role/Permission değişiklikleri
  • Failed authentication attempts

🚀 Deployment Rehberi

🐳 Docker Compose Deployment

📋 Gereksinimler

  • Docker Engine 20.10+
  • Docker Compose 2.0+
  • Minimum 8GB RAM
  • 20GB Disk Space

Kurulum Adımları:

# 1. Projeyi klonlayın cd /Users/gtmac29/projects/secure-box # 2. Environment değişkenlerini ayarlayın (optional) export POSTGRES_PASSWORD="YourStrongPassword123!" export REDIS_PASSWORD="YourRedisPassword123!" export MONGO_PASSWORD="YourMongoPassword123!" # 3. Tüm servisleri başlatın docker-compose up -d # 4. Servis durumlarını kontrol edin docker-compose ps # 5. Logları izleyin docker-compose logs -f # 6. Belirli bir servisin loglarını izleyin docker-compose logs -f api-1 # 7. Servisleri yeniden başlatın docker-compose restart # 8. Servisleri durdurun docker-compose stop # 9. Servisleri tamamen kaldırın (volumes korunur) docker-compose down # 10. Servisleri volumes ile birlikte kaldırın (DİKKAT: Veri kaybı!) docker-compose down -v

☸️ Kubernetes Deployment

📋 Gereksinimler

  • Kubernetes Cluster 1.28+
  • kubectl CLI tool
  • Kustomize (optional, kubectl içinde built-in)
  • Container Registry (DockerHub, ECR, GCR, vb.)

Kubernetes Deployment Adımları:

# 1. Docker image'larını build edin cd src/backend docker build -t your-registry/securebox-api:latest -f SecureBox.API/Dockerfile . cd ../frontend docker build -t your-registry/securebox-portal:latest . # 2. Image'ları registry'e push edin docker push your-registry/securebox-api:latest docker push your-registry/securebox-portal:latest # 3. Secrets oluşturun kubectl create secret generic securebox-secrets \ --from-literal=postgres-password=YourPassword \ --from-literal=redis-password=YourPassword \ --from-literal=mongo-password=YourPassword \ --from-literal=jwt-secret=YourJwtSecret \ -n securebox # 4. Development ortamı için deploy cd kubernetes/overlays/dev kubectl apply -k . # 5. Production ortamı için deploy cd kubernetes/overlays/prod kubectl apply -k . # 6. Deployment durumunu kontrol edin kubectl get pods -n securebox kubectl get services -n securebox # 7. Logs kontrol kubectl logs -f deployment/securebox-api -n securebox # 8. Port forwarding (local test) kubectl port-forward service/securebox-nginx 8080:80 -n securebox
