🏛️ Sistem Katmanları

🎨 1. Frontend Katmanı (Presentation Layer)

Kullanıcılarla etkileşim sağlayan, modern ve responsive arayüz katmanıdır.

Angular Web Portal

  • Teknoloji: Angular 18+ Standalone
  • UI Framework: Angular Material
  • State Management: RxJS
  • Routing: Angular Router with Guards
  • HTTP Client: Angular HttpClient

Özellikler

  • Kullanıcı kimlik doğrulama ve oturum yönetimi
  • Dashboard ve istatistikler
  • Anahtar ve sertifika yönetimi
  • Kullanıcı ve rol yönetimi
  • Audit log görüntüleyici

Güvenlik

  • JWT token storage (localStorage/sessionStorage)
  • Route guards (role-based)
  • HTTPS zorunlu (production)
  • XSS koruması (Angular sanitization)
  • CSRF token yönetimi

⚙️ 2. API Katmanı (Application Layer)

İş mantığının yönetildiği, kimlik doğrulama ve yetkilendirmenin yapıldığı katman.

ASP.NET Core 9 API

  • Framework: ASP.NET Core 9
  • ORM: Entity Framework Core
  • API Docs: Swagger/OpenAPI
  • Logging: Serilog
  • Deployment: 2+ Replicas

Controllers

  • AuthController - Login, logout, token yenileme
  • UsersController - Kullanıcı CRUD işlemleri
  • RolesController - Rol ve izin yönetimi
  • KeysController - Anahtar CRUD, retrieve, rotate
  • CertificatesController - Sertifika yönetimi
  • AuditController - Audit log sorgulama

Services (Business Logic)

  • AuthService - Kimlik doğrulama
  • UserService - Kullanıcı yönetimi
  • KeyService - Anahtar yaşam döngüsü
  • EncryptionService - Şifreleme/deşifreleme
  • AuditService - Audit logging
  • MessageBrokerService - RabbitMQ entegrasyonu

🔐 Authentication & Authorization

  • JWT Tokens: Access token (15 dakika) + Refresh token (7 gün)
  • Roller: Admin, Client, Service (+ özel roller)
  • İzinler: Resource-Action based (örn: Key.Read, Certificate.Create)
  • Triple Auth: Hassas işlemler için Token + Certificate + Password

🗄️ 3. Veri Katmanı (Data Layer)

Tüm verilerin kalıcı olarak saklandığı ve yönetildiği katman.

PostgreSQL (Ana Veritabanı)

  • Versiyon: PostgreSQL 16 Alpine
  • Amaç: İlişkisel veri (ACID)
  • Tablolar: Users, Roles, Keys, Certificates, Audit
  • Özellikler: Foreign keys, indexes, triggers
  • Backup: Otomatik daily backups

Redis (Cache & Session)

  • Versiyon: Redis 7 Alpine
  • Amaç: Cache ve session yönetimi
  • Kullanım: JWT blacklist, metadata cache
  • TTL: Key bazlı yaşam süresi
  • Persistence: AOF (Append Only File)

MongoDB (Log Store)

  • Versiyon: MongoDB 7
  • Amaç: Yüksek hacimli log verisi
  • Collections: audit_logs, key_access_logs
  • Retention: 90 gün (varsayılan)
  • Indexing: Timestamp, userId, action

📊 Veritabanı Şeması (PostgreSQL)

Tablo Açıklama Önemli Kolonlar
Users Sistem kullanıcıları UserId, Username, Email, PasswordHash, IsActive
Roles Kullanıcı rolleri RoleId, RoleName, Description, IsSystem
Permissions İzin tanımları PermissionId, Resource, Action, Description
Keys Şifrelenmiş anahtarlar KeyId, Name, EncryptedValue, CertificateId, Status
Certificates X.509 sertifikaları CertificateId, Thumbprint, Subject, NotAfter
AuditTrails Genel audit kayıtları AuditId, UserId, Action, Resource, Timestamp
KeyAccessLogs Anahtar erişim geçmişi AccessLogId, KeyId, AccessedBy, IPAddress

📡 4. Messaging & Observability Katmanı

Asenkron mesajlaşma ve sistem izleme altyapısı.

RabbitMQ

  • Versiyon: RabbitMQ 3 Management
  • Kuyruklar:
  • - key_rotation_queue
  • - certificate_expiry_queue
  • - audit_event_queue
  • Pattern: Publisher-Subscriber
  • Features: Dead-letter queue, retry logic

ELK Stack

  • Elasticsearch: Log indexing ve search
  • Logstash: Log aggregation pipeline
  • Kibana: Visualization dashboard
  • Use Cases: Security analysis, monitoring
  • Retention: 30 gün (configurable)

🌐 5. Altyapı & Networking Katmanı

Container orchestration, load balancing ve reverse proxy altyapısı.

Nginx (Reverse Proxy)

  • TLS termination (HTTPS)
  • Load balancing (round-robin)
  • Rate limiting
  • Static file serving
  • Health check endpoints

Docker Compose

  • 11 container servisi
  • 3 network (frontend, backend, monitoring)
  • 5 volume (persistent data)
  • Health checks tüm servisler
  • Dependency management

Kubernetes (Production)

  • Deployment manifests
  • Services (LoadBalancer, ClusterIP)
  • ConfigMaps ve Secrets
  • Persistent Volumes
  • Horizontal Pod Autoscaling

🔄 Veri Akış Senaryoları

🔐 1. Kullanıcı Login İşlemi

Adım 1: Kullanıcı portal üzerinden username ve password girer
Adım 2: Angular uygulaması POST /api/v1/auth/login isteği gönderir
Adım 3: Nginx, isteği API instance'larından birine yönlendirir
Adım 4: AuthController, AuthService.LoginAsync() çağırır
Adım 5: AuthService, PostgreSQL'den kullanıcıyı sorgular
Adım 6: Password hash doğrulanır (BCrypt)
Adım 7: JWT access token (15dk) ve refresh token (7 gün) oluşturulur
Adım 8: Refresh token PostgreSQL UserSessions tablosuna kaydedilir
Adım 9: LastLoginAt güncellenir, audit log MongoDB'ye yazılır
Adım 10: Token'lar kullanıcıya döndürülür ve portal'da localStorage'a kaydedilir

🔑 2. Anahtar Oluşturma İşlemi

Adım 1: Kullanıcı portal üzerinde "Create Key" formunu doldurur
Adım 2: POST /api/v1/keys isteği JWT token ile gönderilir
Adım 3: JWT middleware token'ı doğrular ve kullanıcıyı belirler
Adım 4: Authorization middleware Key.Create iznini kontrol eder
Adım 5: KeysController, KeyService.CreateKeyAsync() çağırır
Adım 6: KeyService, seçilen sertifikayı PostgreSQL'den getirir
Adım 7: EncryptionService, key value'yu AES-256-GCM ile şifreler
Adım 8: Şifrelenmiş key PostgreSQL Keys tablosuna INSERT edilir
Adım 9: RabbitMQ üzerinde audit_event_queue'ya mesaj publish edilir
Adım 10: AuditService, PostgreSQL AuditTrails ve MongoDB'ye log yazar
Adım 11: Key metadata (şifresiz) kullanıcıya response olarak döndürülür

🔓 3. Anahtar Retrieve (Triple Authentication)

Adım 1: Kullanıcı portal'da "Retrieve Key" butonuna tıklar
Adım 2: Portal, certificate ve password ister (Triple Auth)
Adım 3: POST /api/v1/keys/{keyId}/retrieve isteği gönderilir
Adım 4: JWT token doğrulanır (1. faktör)
Adım 5: Certificate thumbprint kontrol edilir (2. faktör)
Adım 6: User password tekrar doğrulanır (3. faktör)
Adım 7: KeyService, encrypted key'i PostgreSQL'den getirir
Adım 8: EncryptionService, private key ile deşifre eder
Adım 9: KeyAccessLogs tablosuna erişim kaydedilir (IP, UserAgent)
Adım 10: AccessCount artırılır, LastAccessedAt güncellenir
Adım 11: Audit log MongoDB ve ELK Stack'e gönderilir (Severity: Critical)
Adım 12: Deşifre edilmiş key value kullanıcıya döndürülür
Adım 13: Portal, key'i güvenli şekilde gösterir (copy-to-clipboard)

🔄 4. Otomatik Key Rotation İşlemi

Adım 1: Background worker, expiring keys'leri kontrol eder (daily cron)
Adım 2: Expiring key listesi RabbitMQ key_rotation_queue'ya publish edilir
Adım 3: KeyRotationConsumer, mesajı consume eder
Adım 4: KeyService.RotateKeyAsync() çağrılır
Adım 5: Yeni key value generate edilir (veya admin tarafından sağlanır)
Adım 6: Yeni key aynı certificate ile şifrelenir
Adım 7: Eski key Status='Archived' yapılır
Adım 8: Yeni key Version=2 ile INSERT edilir
Adım 9: Email/Notification service'e bildirim gönderilir (RabbitMQ)
Adım 10: Tüm işlem audit log'a kaydedilir

🔒 Güvenlik Mimarisi

✅ Uygulanan Güvenlik Önlemleri

  • Network Segmentation: Frontend, Backend ve Data katmanları izole network'lerde
  • TLS Everywhere: Tüm external ve inter-service iletişim şifreli (TLS 1.3)
  • Zero-Trust Model: Her request JWT + permission kontrolünden geçer
  • Encryption at Rest: Keys, AES-256-GCM ile certificate-based şifrelenmiş
  • Encryption in Transit: HTTPS/TLS zorunlu (production)
  • Audit Everything: Her kritik işlem PostgreSQL + MongoDB + ELK'da loglanır
  • Triple Authentication: Hassas işlemler için Token + Cert + Password
  • Rate Limiting: Nginx level'da DDoS koruması
  • Soft Delete: Veriler fiziksel olarak silinmez, DeletedAt flag kullanılır
  • Password Policy: Complexity rules, BCrypt hashing
  • Account Lockout: Failed login attempts tracking
  • Token Expiry: Short-lived access tokens (15 min)

⚠️ Dikkat Edilmesi Gereken Noktalar

  • Production ortamında mutlaka TLS sertifikaları (Let's Encrypt/Commercial) kullanılmalı
  • JWT SecretKey environment variable olarak saklanmalı (appsettings.json'da olmamalı)
  • Database şifreleri güçlü ve rotate edilmeli
  • Private key'ler asla repository'e commit edilmemeli
  • Production'da Swagger disable edilmeli (veya IP whitelist)
  • Regular security audit ve penetration test yapılmalı

📈 Ölçeklenebilirlik ve High Availability

Horizontal Scaling

  • API: Nginx arkasında N replica (default: 2)
  • Stateless Design: Session Redis'te, state-free API
  • Kubernetes: HPA ile otomatik scaling

Database Scaling

  • PostgreSQL: Master-Slave replication
  • Redis: Clustering (Redis Sentinel/Cluster)
  • MongoDB: Replica Set (3+ nodes)

Load Balancing

  • Nginx: Round-robin algorithm
  • Health Checks: /health endpoint monitoring
  • Cloud LB: AWS ALB, Azure Application Gateway

Async Processing

  • RabbitMQ: Decoupled workload processing
  • Background Jobs: Key rotation, notifications
  • Dead Letter Queue: Failed message handling
