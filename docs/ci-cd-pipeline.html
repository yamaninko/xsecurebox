📋 CI/CD Genel Bakış

Secure Box projesi, modern DevOps pratiklerine uygun olarak GitLab CI/CD ve GitHub Actions olmak üzere iki farklı CI/CD platformunu desteklemektedir. Her iki platform da production-ready pipeline'lara sahiptir ve Harbor registry üzerinden Kubernetes cluster'larına otomatik deployment yapabilir.

✅ Pipeline Özellikleri

  • Otomatik Docker image build ve push
  • Unit test ve code coverage raporlama
  • Harbor private registry entegrasyonu
  • Kubernetes otomatik deployment
  • Environment-based deployment (dev, prod)
  • Manuel approval mekanizması
  • Rollback desteği
  • Health check ve smoke tests

🦊 GitLab CI/CD Pipeline

📄 Pipeline Dosyası: .gitlab-ci.yml

Tek dosyada tüm pipeline tanımlaması. 5 stage'li professional CI/CD akışı.

Pipeline Stages

🔨 1. Build

  • API Docker image build
  • Portal Docker image build
  • Docker BuildKit kullanımı
  • Multi-stage optimization
  • Artifact storage (1 saat)

🧪 2. Test

  • .NET unit tests (xUnit)
  • Angular tests (Jasmine)
  • Code coverage raporlama
  • ESLint code quality
  • JUnit XML reports

📤 3. Push

  • Harbor registry login
  • Multi-tag push
  • Image verification
  • Only: main, develop
  • Retry on failure

🚀 4. Deploy

  • Manuel trigger (güvenlik)
  • Development environment
  • Production environment
  • Kubernetes deployment
  • Rollout monitoring

🧹 5. Cleanup

  • Docker resource pruning
  • Unused image cleanup
  • Otomatik çalışma
  • Disk space optimization

Kurulum Adımları

1 GitLab Variables Ayarla

Settings > CI/CD > Variables sayfasından aşağıdaki değişkenleri ekleyin:

# Harbor Registry GTECH_REPO_URL = harbor.example.com GTECH_REPO_USERNAME = robot$securebox GTECH_REPO_TOKEN = <your-harbor-token> # Kubernetes KUBECONFIG_DEV = <base64-encoded-kubeconfig> KUBECONFIG_PROD = <base64-encoded-kubeconfig>
2 Pipeline'ı Tetikle

Kodu push ederek pipeline'ı otomatik başlatın:

# Main branch'e push git push origin main # Pipeline otomatik çalışacak: # → build → test → push → (deploy: manuel)
3 Manuel Deployment

GitLab UI'da pipeline sayfasından deploy job'unu manuel olarak çalıştırın.

✅ GitLab CI/CD Avantajları

  • Tek platform çözümü (SCM + CI/CD + Registry)
  • Built-in test reporting ve coverage tracking
  • Native Docker-in-Docker support
  • Environment management ve deployment history
  • Self-hosted runner desteği
  • Enterprise security features

Kurulum Adımları

1 GitHub Secrets Ayarla

Settings > Secrets and variables > Actions sayfasından ekleyin:

# Harbor Registry GTECH_REPO_URL = harbor.example.com GTECH_REPO_USERNAME = robot$securebox GTECH_REPO_TOKEN = <your-harbor-token> # Kubernetes KUBECONFIG = <base64-encoded-kubeconfig>
2 Workflow'ı Tetikle

GitHub Actions sayfasından "Deploy to Kubernetes" workflow'unu çalıştırın.

1 Harbor Credentials Ayarla
export GTECH_REPO_URL="harbor.example.com" export GTECH_REPO_USERNAME="robot\$securebox" export GTECH_REPO_TOKEN="your-token-here"
2 Otomatik Deployment Script Çalıştır
# Deployment script'i çalıştır ./scripts/deploy-to-k8s.sh # Script otomatik olarak: # ✅ Namespace oluşturur # ✅ Harbor secret oluşturur # ✅ Database'leri deploy eder # ✅ Application'ı deploy eder # ✅ Health check yapar # ✅ LoadBalancer IP'yi gösterir

💡 Best Practices

🎯 CI/CD Best Practices

  • Protected branches kullan (main, develop)
  • Production deployment için manuel approval zorunlu
  • Her deployment için rollback stratejisi hazır
  • Smoke test ve health check mutlaka çalıştır
  • Docker layer caching kullan (build süre optimizasyonu)
  • Secrets asla kod'a commit etme (variables/secrets kullan)
  • Image tagging stratejisi: commit-sha + branch + latest
  • Pipeline başarısızlıklarında notification gönder

🔐 Security Best Practices

🔑 Secrets Management

  • GitLab: Protected & Masked variables
  • GitHub: Encrypted secrets
  • Harbor: Robot accounts (not user accounts)
  • Token expiration: Max 1 yıl
  • Regular secret rotation

🛡️ Image Security

  • Private registry kullan (Harbor)
  • Image scanning (vulnerability check)
  • Multi-stage builds (küçük image)
  • Non-root user kullan
  • Sensitive data image'a dahil etme

☸️ Kubernetes Security

  • RBAC permissions (least privilege)
  • Network policies (pod isolation)
  • Resource limits (prevent resource abuse)
  • Pod security policies
  • Secrets encryption at rest

📈 Performance Best Practices

⚡ Build Optimization

  • Docker BuildKit: Parallel build stages
  • Layer Caching: Dockerfile layer order optimizasyonu
  • Multi-stage Builds: Production image'da sadece gerekli dosyalar
  • Artifact Caching: npm, nuget paketlerini cache'le
  • Paralel Jobs: API ve Portal build'leri paralel çalıştır

🐛 Troubleshooting

⚠️ Yaygın Sorunlar ve Çözümleri

1. Build Hatası:

  • Build logs'ı detaylı incele
  • Local'de Docker build test et (docker build --no-cache)
  • Dockerfile syntax kontrol

2. Image Pull Error (ImagePullBackOff):

  • Harbor secret kontrol: kubectl get secret harbor-registry-secret -n securebox
  • Credentials test et: docker login $GTECH_REPO_URL
  • Image tag doğru mu kontrol et

3. Deployment Başarısız:

  • Pod events kontrol: kubectl describe pod <pod-name> -n securebox
  • Pod logs: kubectl logs <pod-name> -n securebox
  • Resource limits yeterli mi kontrol et

4. Test Başarısız:

  • Test reports'ı incele (GitLab/GitHub UI)
  • Local'de test çalıştır: dotnet test --verbosity detailed
  • Test coverage %80+ olmalı
